# Task Runs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move per-attempt status and timing from the `run_ids` / `run_statuses` JSON arrays on `tasks` into a one-to-many `task_runs` table, and surface each attempt's times on the logs endpoint and its UI picker.

**Architecture:** `TaskRun` rows are inserted by `register_run` (host, container or Pod) and closed by one status-guarded `UPDATE` (`end_run`) that targets the task's latest row while it is still `RUNNING`. Every ender issues that `UPDATE` only after its task-level write landed, in the same transaction. Readers query the table; `Task.started_at` / `completed_at` stay as the latest-attempt mirror.

**Tech Stack:** SQLModel / SQLAlchemy async, Alembic (autogenerated via GitHub Actions), FastAPI, React + openapi-typescript.

**Spec:** `docs/superpowers/specs/2026-11-01-task-runs-design.md`

## Global Constraints

- No data migration and no compatibility shim: `run_ids` / `run_statuses` are dropped outright.
- Migrations only via the `generate-migration` skill (trigger the workflow with the `devpowers:action-run` skill on branch `ccr-515bb222-pbb3dy`, then `git pull`). Never hand-write one.
- `run_id` stays a snowflake from `get_snowflake_id()`; ClickHouse `task_logs` rows key on it.
- Statuses written to `task_runs.status`: `RUNNING`, `COMPLETED`, `FAILED`, `CANCELLED` only.
- Imports at top of file, three groups; no `Any`; `python-testing-style` for tests; `markdown-style` for docs.
- Run `uv run ruff check . && uv run ruff format --check .` and `uv run pyright` before each commit.

## Review Focus

- A fenced late writer (epoch mismatch) must never stamp the new attempt's row → `test_clear_fences_stale_failure_cleanup` (Task 1) asserts the run rows after the stale call.
- Two enders racing (worker report vs dead-worker sweep) must leave one `FAILED` row, never two writes → `test_dead_worker_sweep_closes_run_once` (Task 1).
- `register_run` on a missing task must raise, not silently insert an orphan → `test_register_run_missing_task_raises` (Task 1).
- Deleting a job must take its `task_runs` with it → `test_delete_job_removes_task_runs` (Task 1).
- A task with runs but no logs must still report `available=False` with its attempts' times → `test_logs_attempts_carry_times` (Task 2).
