# Worker-Owned Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the docker/kubernetes runner choice from the job (`runner_mode`) to the execution worker's environment (`AAICLICK_RUNNER`), leaving users only `--image` / `--build`.

**Architecture:** The worker reads `AAICLICK_RUNNER` once at startup and at every container dispatch; the job row carries no runner state, only an optional Pod `resources` snapshot. Submission resolves a task's `image_source` (prebuilt / build / NULL) from the user's `image` / `build` inputs and the registration's defaults; dispatch pairs that source with the worker's runner. Cluster settings (namespace, service account, pull secret) are env-only on the worker.

**Tech Stack:** Python 3.10+, SQLModel/SQLAlchemy, Alembic (autogenerated via the `generate-migration` GitHub workflow), pytest (`orch_ctx` / `orch_ctx_no_ch` fixtures, chdb + SQLite locally), React + `openapi-typescript` for `src/api/schema.ts`.

**Spec:** `docs/designs/orchestration.md` sections "Worker runner", "Runners & Entry Types", "Image source"; `docs/designs/kubernetes_runner.md` sections "Configuration", "Selection and dispatch".

## Global Constraints

- All imports at the top of each file; no inline imports (ruff `PLC0415`).
- Closed string sets are `Literal` + module constants, never `Enum`; DB columns stay plain `String` / `Boolean` / `JSON` with no CHECK constraints.
- Env is read inside functions at call time via `os.environ.get`, never at import scope.
- `NamedTuple` for fixed-field records; named attribute access, not positional unpacking.
- No history comments (`# Removed ...`); no `__all__`; no `Any` shortcuts.
- Never hand-write a migration file: autogenerate via the workflow and commit it as generated. No backwards compatibility: existing `runner_mode` / `kubernetes_config` / `runner` values are dropped, not migrated.
- Test files follow `python-testing-style`: flat, end-to-end over internal, parametrize input/expected clusters, delete tests whose behaviour no longer exists.
- Docs in subdirectories follow `markdown-style`; run `shortify` after editing them.
- Commit after each task; commits end with the attribution lines from the session reminder.

## Review Focus

- A worker with `AAICLICK_RUNNER` unset claims a task with an `image_source`: the task must fail with a message naming `AAICLICK_RUNNER`, and the worker loop must keep running. Pinned in Task 2 (`test_resolve_dispatch_without_worker_runner_raises`).
- `AAICLICK_RUNNER=Docker` or `=podman`: `execution-worker start` must exit before touching the database, naming the allowed values. Pinned in Task 1 (`test_validate_worker_runner_rejects_unknown`, `test_execution_worker_start_rejects_bad_runner`).
- `run-job --image X --build`: rejected as mutually exclusive, not silently resolved to one of them. Pinned in Task 4 (`test_run_job_image_and_build_mutually_exclusive`).
- `register-job --git-remote X` without `--build`: rejected ("require build") rather than stored as a dead default. Pinned in Task 4 (`test_registration_rejects_build_modifiers_without_build`).
