# De-tenant the Installation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove multi-tenancy from an aaiclick installation, leaving RBAC as `viewer` / `member` / `admin`, and squash the migration chain to one tenancy-free initial schema.

**Architecture:** Tenancy is a column (`tenant_id`), a contextvar (`aaiclick/tenancy.py`), a request header (`X-Tenant-Id`), a table-name prefix (`p_<tenant_id>_`) and a membership edge (`tenant_memberships`). All five are removed; authority collapses to one `users.role` column bridged to the existing scope ladder by `ROLE_SCOPES`. Everything `superadmin` gated moves to `admin`. Work proceeds bottom-up through the import graph — security → models → store → view models → internal API → server → CLI — then the data plane, the schema, the SPA, and the docs.

**Tech Stack:** Python 3.10+, SQLModel/SQLAlchemy, Alembic (autogenerate via GitHub Actions), FastAPI, FastMCP, pytest (chdb + SQLite locally), Vite/React/TypeScript, openapi-typescript.

**Spec:** `docs/superpowers/specs/2026-09-15-detenant-installation-design.md`

## Global Constraints

- Roles are exactly `viewer` / `member` / `admin`; scopes are exactly `read` / `write` / `admin`. `superadmin` disappears from both ladders.
- `users.role` is a plain `String` column typed with the `Role` literal — no DB CHECK constraint (CLAUDE.md, "Prefer Literal").
- `require_superadmin` → `require_admin` is reviewed **per call site**, never bulk-substituted (spec, "Collapsing a scope rung can widen access").
- Persistent tables are `p_<name>`; `MAX_PERSISTENT_NAME_LEN` stays `128`.
- The migration chain is one `initial_schema` revision generated by the `generate-migration` workflow. Never hand-write a migration (CLAUDE.md, "Alembic Migrations").
- All imports at the top of the file; no `Any`; no `__all__`; no history comments (CLAUDE.md, "Coding Guidelines").
- Tests follow `python-testing-style`: tests that only proved a tenant filter are deleted, not rewritten.
- Docs in subdirectories follow `markdown-style`: setext title, `#`/`##` only, name-based implementation references.

## Spec refinement made here

The spec says `aaiclick setup` seeds an initial admin. The installation already has that mechanism: `_seed_admin` in `aaiclick/server/app.py` inserts the `AAICLICK_ADMIN_USERNAME` / `AAICLICK_ADMIN_PASSWORD` user at server startup when `users` is empty. This plan keeps that single seed (now `role="admin"`, default username `admin`) and simply deletes `_seed_default_tenant` from `setup.py` rather than adding a second seed there.

## How to read the phases

The auth layer is one coupled unit: deleting `Tenant` breaks every importer at once. Phase 1 therefore orders its tasks along the import graph and each task runs **only its own test module**; the whole `auth` / `internal_api` / `server` / CLI suite is expected green only at the **Phase 1 gate**. Phases 2–6 each end green on the full suite.

Run tests with the project venv (`uv sync --extra dev` once). Every command below assumes the repo root as the working directory. `-p no:cov` skips coverage for speed during iteration; the gates run with the default options.

```python
def encode_access_token(*, user_id: int, role: Role, secret: str, ttl: int) -> str:
    now = datetime.now(timezone.utc)
    payload = {
        "sub": str(user_id),
        "role": role,
        "type": TOKEN_TYPE_ACCESS,
        "iat": now,
        "exp": now + timedelta(seconds=ttl),
    }
    return jwt.encode(payload, secret, algorithm="HS256")


def decode_access_token(token: str, secret: str) -> AccessClaims:
    try:
        payload = jwt.decode(token, secret, algorithms=["HS256"])
    except jwt.PyJWTError as exc:
        raise TokenError(str(exc)) from exc
    if payload.get("type") != TOKEN_TYPE_ACCESS:
        raise TokenError("not an access token")
    role = payload.get("role")
    if role not in ROLES:
        raise TokenError("malformed claims")
    try:
        return AccessClaims(user_id=int(payload["sub"]), role=role)
    except (KeyError, ValueError) as exc:
        raise TokenError("malformed claims") from exc
```

```python
def principal_to_scope(principal: Principal) -> ScopeLevel:
    """The one bridge from a principal to the scope it holds. Every gate on
    both surfaces compares this against the level the route or tool declares —
    nothing else is consulted.

    A session resolves through its role via ``ROLE_SCOPES``. A token stands on
    its own scope like a GitHub PAT — the mint ceiling capped it, and demoting
    the owner does not shrink it; revoke it instead. Disabling the owner still
    stops it, which ``resolve_api_token`` checks.

    if principal.scope is not None:
        return principal.scope
    return ROLE_SCOPES[principal.role]
```

```python
        return [tool for tool in tools if _listable(principal, tool)]

    async def on_call_tool(self, context, call_next):
        request = _current_request()
        if request is None or context.fastmcp_context is None:
            return await call_next(context)
        tool_name = context.message.name
        # Named before the gate, so the audit row identifies the tool even when
        # the call is refused.
        audit_state(request.scope).action = tool_name
        tool = await context.fastmcp_context.fastmcp.get_tool(tool_name)
        if tool is None:
            raise ToolError(f"unknown tool {tool_name!r}")
        try:
            authorize_tool(await _principal_for(request), tool.tags)
        except (Unauthorized, Forbidden) as exc:
            # MCP has no per-call HTTP status; a refusal is a tool error.
            raise ToolError(f"{tool_name}: {exc}") from exc
        return await call_next(context)
```
