# Sandbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/sandbox` page where any signed-in user submits one Python file of `@task`/`@job` definitions; the server commits it to the `AAICLICK_SANDBOX` git repo and the background worker runs every job in it once as a git-build job.

**Architecture:** A new `aaiclick/sandbox/` package owns the git clone and the `ast` scan. A `sandbox_files` row records each submission. The background worker turns pending rows into `run_job(name, entrypoint, git_remote=, git_sha=, run_type="SANDBOX")` calls; everything after that is the existing build-and-run path, including the default Dockerfile. The SPA gets two routes.

**Tech Stack:** FastAPI, SQLModel, Alembic (via the `generate-migration` skill), git CLI through `aaiclick.orchestration.execution.cli.run`, React + TanStack Query, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-09-sandbox-design.md`

## Global Constraints

- Imports at the top of every file, three groups; no inline imports (CLAUDE.md).
- String sets are `Literal` plus module constants, stored as plain `String` columns, no CHECK constraint.
- No `Any`; no `global` (use `ContextVar`); `NamedTuple` for fixed-shape returns.
- Only the API server reads `AAICLICK_SANDBOX`. The worker learns the remote from the row; the execution worker from `image_source`.
- The source file is never imported on the API server or the background worker.
- Tests: e2e first; a unit test only where the plan names one. Follow the `python-testing-style` skill for layout.
- Docs under `docs/` follow the `markdown-style` skill; run `shortify` after editing.
- Commit after every task; no model identifiers in commits.

## Review Focus

1. A name that is valid but collides within one second (two users, same name, same `ts`) — the path must stay unique: the second submission gets a `path` suffix `_2`. Test added in Task 3.
2. A source file whose `@job` function is also `async def` — `find_job_functions` must accept `AsyncFunctionDef`. Test in Task 2.
3. A remote whose default branch is not `main` (e.g. `master`) — the clone must push to that branch, not create `main`. Test in Task 3.
4. A row whose `run_job` fails on the second job of three — `job_ids` keeps the first id and `error` names the second job. Test in Task 6.
5. A viewer role user — may submit (the sandbox is open to everyone) and sees no `remote` in `config`. Test in Task 5.

### Task 3: Git repository

**Files:**
- Create: `aaiclick/sandbox/repo.py`
- Test: `aaiclick/sandbox/test_repo.py`

**Interfaces:**
- Consumes: `aaiclick.orchestration.execution.cli.run(*argv, check=..., stream=False) -> (rc, stdout, stderr)`; `aaiclick.backend.get_local_root() -> Path`.
- Produces:
  - `class SandboxGitError(RuntimeError)` — any git failure, message is the git stderr.
  - `class SandboxPushRejected(SandboxGitError)` — second non-fast-forward rejection.
  - `class Author(NamedTuple)`: `name: str`, `email: str`.
  - `class Committed(NamedTuple)`: `path: str`, `sha: str`.
  - `class SandboxRepo`: `__init__(self, remote: str, workdir: Path | None = None)` (default `get_local_root() / "sandbox" / "repo"`), attribute `remote: str`; `async def commit_file(self, path: str, content: str, *, author: Author, message: str) -> Committed`; `async def read_file(self, path: str, sha: str) -> str`.
  - `def submission_path(name: str, now: datetime) -> str` → `f"{now:%Y%m%d}/sb_{int(now.timestamp())}_{name}.py"`.
  - `def module_parts(path: str) -> tuple[str, str]` → `("YYYYMMDD", "sb_<ts>_<name>")`.
  - `def get_sandbox_repo() -> SandboxRepo | None` — `None` when `AAICLICK_SANDBOX` is unset; otherwise one instance per process held in a private `ContextVar`-backed accessor with a `@contextmanager` `sandbox_repo_override(repo)` for tests.
  - Module constants: `COMMITTER = Author("aaiclick", "sandbox@aaiclick")`, `ENV_SANDBOX = "AAICLICK_SANDBOX"`.

Behavior of `commit_file`:
1. Under one module-level `asyncio.Lock`, ensure the clone exists (`git clone --depth=1 -- <remote> <workdir>`; an empty remote clones with a warning and no HEAD).
2. Resolve the branch: `git symbolic-ref --short refs/remotes/origin/HEAD` → strip `origin/`; when that fails (empty remote) the branch is `main` and the first commit is made on an orphan `main`.
3. `fetch origin`, `reset --hard origin/<branch>` (skipped on the empty remote), write the file (if `path` exists already, append `_2`, `_3`… before `.py` and return the adjusted path), `add`, `commit` with `-c user.name/user.email` for the committer and `--author "name <email>"`, `push -u origin HEAD:<branch>`.
4. On push stderr containing `rejected`/`non-fast-forward`: once, `fetch` + `reset --hard origin/<branch>` + re-apply the write/commit + push; a second rejection raises `SandboxPushRejected` after resetting the clone.

async def test_rejected_push_retries_once_then_raises(tmp_path):
    remote = _bare(tmp_path, seed=True)
    repo = SandboxRepo(str(remote), tmp_path / "clone")
    await repo.commit_file("20261009/sb_1_a.py", "x = 1\n", author=Author("u", "u@x"), message="m")
    _push_competing_commit(remote, tmp_path / "other")          # the retry absorbs this one
    ok = await repo.commit_file("20261009/sb_2_b.py", "y\n", author=Author("u", "u@x"), message="m")
    assert _git(remote, "rev-parse", "main") == ok.sha
    with patch.object(repo, "_push", side_effect=_reject_twice()):
        with pytest.raises(SandboxPushRejected):
            await repo.commit_file("20261009/sb_3_c.py", "z\n", author=Author("u", "u@x"), message="m")


def test_submission_path_and_module_parts():
    now = datetime(2026, 10, 9, 12, 0, tzinfo=timezone.utc)
